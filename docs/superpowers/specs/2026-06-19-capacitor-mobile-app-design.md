# PaperPilot Mobile App — Capacitor Wrapper Design

**Date:** 2026-06-19
**Status:** Approved (design)
**Branch:** `mobile-app-fe`

## Goal

Ship PaperPilot as native iOS + Android apps that reuse the existing React web
frontend **unchanged**, talk to the same backend, and leave the current web
deployment (S3 + CloudFront) untouched. Mobile is delivered via **Capacitor**
(the native runtime from the Ionic team) — not the Ionic Framework UI library.

Explicit non-goal: this does **not** teach the Ionic Framework component
library. It teaches the Capacitor native toolchain. Accepted by the user.

## Approach

Wrap the existing `frontend/dist` Vite build in a Capacitor native shell. No UI
rebuild. A new sibling `mobile/` folder is the Capacitor root; `frontend/`
stays as-is.

```
paperpilot/
├─ frontend/             # UNCHANGED — web app, deploys to S3/CloudFront
│  └─ dist/              # Vite build output (gitignored)
└─ mobile/               # NEW — Capacitor root
   ├─ package.json       # @capacitor/core, @capacitor/cli, ios, android
   ├─ capacitor.config.ts
   ├─ ios/               # generated by `npx cap add ios`
   └─ android/           # generated by `npx cap add android`
```

`capacitor.config.ts`:
- `appId`: `com.leongxinnan.paperpilot` (reverse-DNS, stable for store identity)
- `appName`: `PaperPilot`
- `webDir`: `../frontend/dist` — Capacitor packages the exact same React build.

## Build / run flow

```bash
# 1. Build the web app with the mobile API target baked in (Vite env is build-time)
VITE_API_URL=https://api.paperpilot.leongxinnan.com pnpm --dir frontend build

# 2. Copy dist + native plugins into the native projects
cd mobile && npx cap sync

# 3. Run
npx cap run ios          # or: npx cap open ios     → Xcode → simulator
npx cap run android      # or: npx cap open android → Android Studio
```

`VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` are baked the same way at
build time. A convenience wrapper script (e.g. `mobile/scripts/build-web.sh` or
an `.env.mobile` file consumed by the frontend build) MAY be added to avoid
retyping the env — decided during implementation, not required by this design.

## Required changes outside `mobile/`

1. **Backend CORS (`backend/.../api.py`).** Native WebView origin is
   `capacitor://localhost` (iOS) and `http://localhost` / `https://localhost`
   (Android), not the web domain. Add these to the allowed origins. ~2 lines.
   This is the one backend change required for v1.

2. **`.gitignore` for `mobile/`.** Ignore generated native artifacts:
   `mobile/ios/App/Pods`, `mobile/ios/App/App/public`, `mobile/android/.gradle`,
   `mobile/android/app/build`, `mobile/android/app/src/main/assets/public`,
   `mobile/node_modules`, Capacitor's copied `public/` dirs. Commit the native
   project scaffolding (`ios/`, `android/`) itself so the app is reproducible.

## Verify on simulator (not assumed)

- **SSE streaming** (`/chat`, `/query`) through the WebView fetch — confirm
  tokens stream live on iOS + Android simulators.
- **File upload** (`<input type=file>`) — iOS needs `NSPhotoLibraryUsageDescription`
  / `NSCameraUsageDescription` strings in `Info.plist`; Android needs the
  file/photo picker to resolve. Confirm a PDF upload completes.
- **Auth session persistence** — Supabase email/password login persists across
  app restarts in the WebView.

## Out of scope (v1)

- **Ionic Framework UI components** — explicitly not used.
- **Native Google OAuth.** Web redirect OAuth breaks inside a WebView. Native
  needs a deep-link redirect (`@capacitor/browser` + custom URL scheme) or a
  native Google sign-in plugin. v1 ships **email/password only**; native OAuth
  is a documented follow-up.
- Native push notifications.
- App Store / Play Store submission, signing, provisioning profiles.
- Custom splash screen / app icon polish — Capacitor defaults for v1.
- Real pnpm-workspace linking between `mobile/` and `frontend/`. `mobile/`
  references `../frontend/dist` by path (a built artifact), so no TS source is
  shared yet. Add workspace linking only if/when shared source is needed.

## Success criteria

- `npx cap run ios` and `npx cap run android` launch PaperPilot in their
  respective simulators.
- A user can log in (email/password), upload a PDF, and get a streaming answer
  with citations — same behavior as web.
- Web deployment is unaffected (no change to `frontend/` source or its CI).

## Follow-ups (post-v1, separate specs)

- Native Google OAuth via deep links.
- App icon + splash branding.
- Store submission pipeline.
- Capacitor plugins for native niceties (status bar, haptics, share sheet).
